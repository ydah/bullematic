Run the code you already test. Review the proposed fix. Apply it, then check the result with the same command.

  1. 1

    Record

    Capture Bullet detections and their call sites while your tests or app run.

    bullematic record -- …

  2. 2

    Preview

    Inspect the planned changes before writing anything to your source files.

    bullematic plan

  3. 3

    Apply

    Rewrite supported queries with Prism. Keep a backup of the original file.

    bullematic apply

  4. 4

    Verify

    Rerun the recorded command and check for remaining N+1 warnings.

    bullematic verify

Small code changes.
Clear boundaries.

Bullematic works from what Bullet observes at runtime. It matches a detection to a query, verifies the association, and rewrites the Ruby syntax tree.

includes preload eager_load
Preview first, apply when ready
Dry-run mode is on by default. Choose your target paths, skip paths, and eager-loading strategy.
A focused fix, backed by evidence
Direct Active Record queries with a clear origin and a verifiable association are candidates for a fix.
Uncertain cases stay with you
Ambiguous origins, dynamic scopes, memoized relations, and cross-method or cross-file relation builders are skipped.

Add Bullematic to a Rails app where Bullet already runs in development or test.

Using RSpec or Minitest? Enable the matching integration before recording your test run.

Set up your integration

Requires Ruby 3.1+ and Bullet 6.0–8.x.

Add to your Gemfile

gem 'bullematic', group: [:development, :test]

Install, then record and review

bundle install

# After setting up your test integration
bundle exec bullematic record -- bundle exec rspec
bundle exec bullematic plan

# When you're ready to write the changes
bundle exec bullematic apply
bundle exec bullematic verify

Review the changes and rerun your tests before committing. Explore configuration
